# V1.2 Sandbox Data Audit Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the WeCom sandbox proof loop into a safer V1.2 sandbox system with persisted cases, audit trail, configurable rules, real-shaped adapters, and UI backed by API data.

**Architecture:** Keep WeCom as the sandbox intake channel. Store normalized events, after-sales cases, decisions, action results, and audit logs in Postgres through Prisma. Keep all external platform mutations mocked, but make adapter interfaces match future Taobao/Douyin integration boundaries.

**Tech Stack:** NestJS, Prisma, PostgreSQL, Next.js, TypeScript, Zod, Socket.IO, existing `@smart-cs-agent/shared` contracts.

---

## Scope

V1.2 should prove the system can run with persisted sandbox data and auditable decisions.

It should not connect real Taobao, Douyin, payment, refund, or production WeCom credentials.

## Definition Of Done

- All five demo payloads create persisted cases.
- Each case stores customer message, decision, action result, and audit logs.
- Low-risk cases still auto-execute through mock adapters.
- Medium-risk cases still require human confirmation.
- High-risk cases still require human takeover.
- Operator UI uses API-backed data.
- Typecheck, lint, build, and API tests pass.

Verification commands:

```bash
npm run test --workspace @smart-cs-agent/api
npm run typecheck --workspaces --if-present
npm run lint --workspaces --if-present -- --max-warnings=0
npm run build --workspaces --if-present
```

## Explicit Non-Goals

- Real Taobao/Douyin credentials.
- Real WeCom production callback verification.
- Real payment/refund execution.
- Billing.
- Multi-tenant role UI.
- Production alerting.

These remain V1.3/V2.0 work.
