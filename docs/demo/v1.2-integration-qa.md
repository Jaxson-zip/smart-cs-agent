# V1.2 集成验收标准

本文档用于验收 V1.2 本地沙盒闭环。它验证沙盒能力，不验证真实淘宝、抖音、企业微信、支付、退款或生产风控能力。

## 验收范围

- Postgres 可本地启动。
- Prisma migration 和 seed 可执行。
- API 可在 `http://localhost:4100` 启动。
- Web 客服台可读取 API 的案件数据。
- 5 个企微沙盒 payload 可通过 `POST /v1/wecom/events` 进入售后决策流程。
- `/v1/cases` 和 `/v1/rules/demo_tenant` 可用于人工验收。

## 必须通过的命令

```powershell
docker compose up -d postgres
npm.cmd run db:migrate
npm.cmd run db:seed
npm.cmd run dev:api
npm.cmd run dev:web
npm.cmd run demo:smoke
```

代码质量检查：

```powershell
npm.cmd run typecheck --workspaces --if-present -- --pretty false
npm.cmd run lint --workspaces --if-present -- --max-warnings=0
```

## 决策验收标准

| 场景 | 输入文件 | 分类 | 风险等级 | 自动化模式 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| 收货地址修改 | `01-address-change-low.json` | `address_change` | `low` | `auto_execute` | 低风险自动处理，可执行模拟改地址/回复动作 |
| 物流查询 | `02-logistics-inquiry-low.json` | `logistics` | `low` | `auto_execute` | 低风险自动处理，可执行模拟物流查询/回复动作 |
| 小额破损补偿 | `03-damage-compensation-low.json` | `damage_compensation` | `low` | `auto_execute` | 低风险自动处理，可执行模拟补偿动作 |
| 补偿被拒 | `04-compensation-rejected-medium.json` | `compensation_rejected` | `medium` | `human_confirm` | 中风险不直接执行，需要客服确认下一步回复或动作 |
| 投诉升级 | `05-complaint-escalation-high.json` | `complaint_escalation` | `high` | `human_takeover` | 高风险必须人工接管，不应自动执行补偿或退款 |

核心规则：

- 低风险：允许 `auto_execute`，可以落地 mock action 和自动回复。
- 中风险：必须 `human_confirm`，系统只能给建议，不直接替客服确认。
- 高风险：必须 `human_takeover`，进入人工接管队列，避免自动执行敏感动作。

## API 验收

健康检查：

```powershell
curl.exe http://localhost:4100/health
```

通过条件：

- HTTP 200。
- 响应 `status` 为 `ok`。

规则接口：

```powershell
curl.exe http://localhost:4100/v1/rules/demo_tenant
```

通过条件：

- HTTP 200。
- 响应包含 `couponCompensationLimit`。
- 响应包含 `highRiskKeywords`。
- 响应包含 `channelCapabilities.taobao` 和 `channelCapabilities.douyin`。

案件接口：

```powershell
curl.exe http://localhost:4100/v1/cases
```

通过条件：

- HTTP 200。
- 返回数组。
- seed 后至少包含 5 个示例 case。
- smoke 后能看到新写入的 5 个沙盒 case。
- 每个 case 至少包含 `caseId`、`merchantId`、`channel`、`category`、`riskLevel`、`automationMode`、`customerMessage`。

事件接口：

```powershell
npm.cmd run demo:smoke
```

通过条件：

- 5 个场景都返回 HTTP 200。
- 每个响应包含 `afterSalesCase`。
- smoke 输出中 5 行的 `category`、`riskLevel`、`automationMode` 均为 `OK`。
- 失败时脚本输出可操作错误，不出现未处理异常堆栈。

## Web 客服台验收

打开：

```text
http://localhost:3000
```

通过条件：

- 页面能加载案件列表。
- 列表或详情能展示售后分类、风险等级、自动化模式。
- 低风险自动处理 case 不应混入需要人工接管的高风险队列。
- 中风险 case 应体现待确认状态或等价的客服确认动作。
- 高风险 case 应体现人工接管状态或等价的客服接管动作。
- 页面不应暴露 prompt、RAG、向量库、内部 tool trace 等实现细节给客服。
- 审计信息可用于说明事件接收、分类、风险判断、动作执行或接管建议的过程。

## 数据与审计验收

通过条件：

- `NormalizedChannelEvent` 记录每个沙盒输入事件。
- `AfterSalesCase` 持久化每个决策结果。
- `CaseMessage` 保存客户消息；低风险自动回复场景应保存系统/agent 回复。
- `CaseAction` 记录 mock action，低风险自动执行为 `success` 或等价完成状态，中高风险为 `pending` 或等价待处理状态。
- `AuditLog` 至少能追踪 `event_received`、`category_decision`、`risk_decision`；自动执行场景还应能追踪动作或回复结果。

## 不属于 V1.2 验收的事项

- 真实企业微信回调签名、重试、IP 白名单。
- 真实淘宝/抖音店铺授权。
- 真实退款、赔付、发券、改地址。
- 生产级权限、审计合规、告警和灾备。
- 大模型线上质量评测或人工标注闭环。

## 已知风险

- 沙盒分类依赖当前演示文本和关键词规则，不能代表生产泛化能力。
- 重复手动发送相同 payload 应复用同一个 `case_${externalMessageId}` 工单，并刷新该工单的消息、动作和审计记录；smoke 脚本默认添加运行后缀，是为了每次演示生成一组新的工单。
- API 健康检查不等于数据库健康，仍需通过 `/v1/rules/demo_tenant`、`/v1/cases` 和 smoke POST 验证 DB 路径。
- Web 端口改为 3100 时，需要同步 API 的 `WEB_ORIGIN`，否则浏览器侧实时连接可能被 CORS 拦截。
